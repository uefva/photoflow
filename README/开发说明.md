# photoflow 开发说明

面向要改代码的人。使用和工作流本身见根目录 `README.md` 与 `photoflow-工作流说明.md`。

## 一、代码结构

```
src/
  cli.rs       参数解析、根目录解析、四个命令的分发
  config.rs    配置文件读写（含手写 JSON 解析）
  naming.rs    批次名/路径/后缀剥离/文件枚举/扩展名判定
  ingest.rs    从卡分发（RAW / 原图 / 视频三类）
  archive.rs   归档已修照片的原图
  doctor.rs    全库体检
  newcmd.rs    建批次
  fsops.rs     复制、移动、校验、无覆盖改名
  sha256.rs    流式 SHA-256
  plan.rs      预演清单指纹
  progress.rs  @@PROGRESS@@ / @@PLAN@@ 协议
  timefmt.rs   时间格式化
  ui.rs        终端配色与执行确认
gui/           Tauri 2 桌面界面：src-tauri 是 Rust 壳，ui/ 是静态前端
tests/         集成测试，跑真实二进制
```

零第三方依赖（`[dependencies]` 是空的）：SHA-256、JSON、日期计算都自己实现，方便在没网的机器上直接编译。

界面不自己实现任何文件操作——它把参数拼成命令行，用隐藏的 `__cli` 模式调用**自己这个 exe**，再把输出流回界面。界面和命令行永远是同一份代码、同一个二进制。

## 二、构建与运行

```
cargo build --release        # 产物 target/release/photoflow.exe
cd gui/src-tauri
cargo build --release        # 产物 target/release/photoflow-gui.exe，前端资源已编进去
# 或者要安装包：
cargo install tauri-cli --version "^2"
cd ..                        # 回到 gui/
cargo tauri build
```

所有 `cargo` 命令都在仓库根目录下执行（GUI 那条 `cd gui/src-tauri` 除外）。

## 三、测试

`cargo test` —— 47 条：29 单元 + 18 集成。

单元测试覆盖命名、后缀剥离、清单指纹、SHA-256（含标准向量与 Windows 栈尺寸回归）、复制移动、config JSON、视频扩展名判定。

集成测试在临时目录里合成照片库，用 `CARGO_BIN_EXE_photoflow` 跑真实二进制，判据和用户实际用法一致：侧车闸门、多版本只归档一次、降噪中缀、冲突不覆盖、重复份清理、多格式歧义、单候选跨格式、指纹锁清单、路径穿越拦截、分发改名不顶名、不留临时文件、目录撞车拒绝执行、视频分流与归档忽略。

## 四、几个必须守住的坑

**跨卷绝不靠 `std::fs::rename`。** 它在 Windows 上走 `MoveFileEx(MOVEFILE_COPY_ALLOWED)`，跨卷会自己悄悄复制再删、且不校验。同一卷用「硬链接 + 删源」（目标已存在则失败，天然不覆盖）；Windows 上直接调不带 `COPY_ALLOWED` / `REPLACE_EXISTING` 的 `MoveFileExW`，跨卷如实返回错误码 17，再进入真正的「复制 → 校验 → 删源」。

**复制后要补 mtime。** `fs::copy` 不拷时间；计划指纹吃 mtime，不补的话重跑同一张卡会被判成全新照片。复制后显式 `set_times`。

**跨卷错误码分平台。** Unix 18 / Windows 17，用 `raw_os_error()` + `cfg` 分别判，不做「一把梭」的 errno 比较。

**哈希读缓冲必须小。** `hash_reader` 的缓冲是栈上数组；Windows 主线程默认栈 1 MiB，曾用 1 MiB 缓冲导致 `has overflowed its stack`。现在是 64 KiB，并有一条 1 MiB 栈线程的回归测试守着。

**界面里的 `window.confirm` 是异步的。** Tauri 的 dialog 插件把它换成了返回 Promise 的版本，前端必须 `await`，否则拿到的是恒真的 Promise，弹窗还没点就已经开跑。

**目录必须互不相同。** 原图目录和归档目录撞在一起时，归档会把原图当成「已归档的重复份」删掉。配置层会拒绝，`archive` 里另有一道真实路径比较兜底（符号链接 / junction 也拦）。

## 五、验证情况

- `cargo test`：47 条（29 单元 + 18 集成）全绿。
- Windows 实机：CLI 和 Tauri 界面都已编译并实际使用过。期间发现并修掉两个问题——`--verify` 的哈希读缓冲撑爆主线程栈；界面里的确认框没拦住执行。
- 跨平台分支：开发环境是 Linux，另做过 `cargo check --target x86_64-pc-windows-gnu`，`MoveFileExW` / `GetTimeZoneInformation` 这些 `cfg(windows)` 代码都能编过。

第一次在自己的库上用，仍建议先只预演、再拿一个小批次试 `--apply`，重点看中文文件名、以及原图和归档同卷时是否走改名（应该瞬间完成，不走复制）。

## 六、已知限制

- 只处理「一张成品对应一张原图」。同一张原图导出多个版本（`-ed` 和 `-ed2` 并存）时只归档一次，其余会提示。
- 归档匹配基于文件名，不读 EXIF 或图像内容；成品与原图字节必然不同，无法用哈希校验配对关系。
- 批次名格式校验是建议性的，`--force` 可以放过；路径安全校验不可绕过。
- 依赖 NAS 相册能按目录排除索引。
