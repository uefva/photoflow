## 一、目录结构与用途

| 目录 | 放什么 | 极相册索引 |
|---|---|---|
| `01-本地缓存` | 本地缓存 | 未确认 |
| `02-视频`、`06_my大疆v5视频` | 视频 | 是 |
| `03_缓存-调色ed` | 修图成品，文件名带 `-ed` | 是 |
| `04_RAW原图` | 相机 RAW 底片，只进不改 | 否 |
| `05_JPG图` | 待处理的相机直出 JPG | 是 |
| `07_鸟图-succ`、`09_other人像`、`10_比特` | 从批次里手工精选的副本 | 是 |
| `08_堆栈素材` | 堆栈 / 合成中间素材 | 否 |
| `99_图库\原图JPG归档` | 已修照片的原图 JPG，含脚本日志 `_logs` | 否 |

分成三层看：

- **底片层** `04`：原始 RAW，永久只读。
- **工作层** `05` + `03`：还没修的原图，和已经修好的成品。
- **归档层** `99`：修完之后不再需要出现在时间线里的原图。

专题目录 07 / 09 / 10 是你事后从批次里挑出来复制过去的，与批次正交，脚本不碰。
视频由 `ingest` 复制到视频目录（默认 `02-视频`，可在设置里改），归档和体检都不会把它当照片。

各目录的名字都可以改：界面最右边的「设置」页签，或者直接编辑 `%USERPROFILE%\.photoflow.json` 里的 `dirs`。改完命令行和界面一起生效，不会自动搬动已有的文件夹。目录不能重名——界面保存时会拦，命令行读到撞车的配置也会直接拒绝执行。

## 二、批次命名

统一 `YYYY-MM-DD-地点`，月日补零，地点里不要有空格。

`04`、`05`、`03`、`99` 四处用同一个批次名，一一对应。用 `photoflow new` 一次性建齐四个目录，避免手打四处打出差异。

实际库里目前有几处例外，脚本会报出来但不擅自改：

- `2026-7-25-大通山`：月份没补零
- `比特`：没有日期
- `深圳湾公园` / `深圳湾公园-1`、`光明欢乐田园` / `光明欢乐田园-1`：同一场拍拆成了两个批次名，一个放 JPG 一个放 RAW

## 三、日常流程

### 1. 建批次

```
photoflow new 2026-11-26-地点
photoflow new 2026-11-26-地点 --apply
```

一次建好 `04` / `05` / `03` / `99` 四个同名目录。默认只预演，看完清单再加 `--apply`。

批次名会做安全校验：含有 `/ \ : * ? " < > |`、控制字符、首尾空格、结尾点号，或者整个名字是 `.` / `..`，一律拒绝。这一项 `--force` 也绕不过。`--force` 只放过日期格式不规范。

### 2. 从卡里分发

```
photoflow ingest F:\DCIM 2026-11-26-地点
photoflow ingest F:\DCIM 2026-11-26-地点 --apply
```

- RAW（`.cr2 .cr3 .nef .arw .raf .dng .orf .rw2 .pef .srw` 等）进 `04`
- JPG / HEIC / PNG / TIFF 进 `05`
- 视频（.mp4 / .mov 等）进视频目录 `<视频目录>\<批次>\`，不参与照片流程
- 其余文件（文档、xmp 等）跳过并提示

同名文件的判定：先比大小，大小相同才比 SHA-256。**只有哈希一致才算重复跳过**；内容不同会列为冲突，不覆盖、不静默丢弃。

卡内同名但内容不同的照片，默认列成冲突让你决定；加 `--dedupe` 会自动存成 `IMG_0002_2.JPG`。同一批重复跑是幂等的，已经复制过的会自动跳过。

### 3. 选片修图

Lightroom 从 `04` 读 RAW，选片、调色。用 AI 降噪的话，LR 会派生 `原名-已增强-降噪.dng`，这个不用管，脚本匹配时会自动处理。

### 4. 导出成品

导出预设里两处要配：

- **文件命名**：模板用 `{Filename}-ed`
- **导出位置**：直接指向 `J:\...\03_缓存-调色ed\`，`<批次>` 那一层

配好之后，「导到本机 → 拷到 03 → 逐个改名」这三步就没了，文件名自动带 `-ed`。批量出片用「导出使用上一次设置」。

### 5. 归档原图

```
photoflow archive 2026-11-26-地点
photoflow archive 2026-11-26-地点 --apply
```

脚本扫描 `03\<批次>` 里每个成品，剥掉后缀得到原名，去 `05\<批次>` 找同名原图，移进 `99\<批次>`。没修的原图留在 `05`，继续在极相册可见。

跑完分四类报账：

- **归档 N 个**：真正移动了多少
- **已在归档中**：99 里已有同名同内容，重复跑不会出错
- **内容冲突**：99 里同名但内容不同，拒绝覆盖
- **失败**：IO 错误

匹配规则偏保守：同主名多扩展名、或同扩展名多候选时，只报警不移动，需要你人工确认。

### 6. 定期体检

```
photoflow doctor
```

只读不写，检查八项：四个顶层目录是否都在、批次命名是否合规、04/05 是否缺目录、03 根目录有没有散落文件、05 有没有空目录、有没有「已修但原图还没归档」的漏网之鱼（以及同名另一种格式还留在 05 的情况）、03 里有没有认不出的成品文件、05/03 里有没有视频（只报告，不计未修、不移动）。

最后两项最关键。漏归档就是极相册出现重复照片的唯一原因。

## 四、为什么这样能自动去重

一张照片修完后：

- 成品在 `03`（被索引）
- 原图从 `05`（被索引）挪进 `99`（不索引）

于是极相册里这张照片只剩成品一份。没修的照片原图还在 `05`，显示原图。归档进 `99` 的老照片退出时间线。

结果是每张照片在时间线里只出现一次：修过的看成品，没修的看原图。

## 五、脚本认哪些文件名

| 文件名 | 是否识别为成品 | 匹配到的原图 |
|---|---|---|
| `DSC07287-ed.JPG` | 是 | `DSC07287.JPG` |
| `DSC07287-ed2.JPG` | 是 | `DSC07287.JPG` |
| `DSC07287-ed-2.JPG` | 是 | `DSC07287.JPG` |
| `DSC07287-ed-Edit.JPG` | 是 | `DSC07287.JPG` |
| `DSC07287-已增强-降噪-ed.JPG` | 是 | `DSC07287.JPG` |
| `DSC07287-Enhanced-NR-ed.JPG` | 是 | `DSC07287.JPG` |
| `DSC07287-edited.JPG` | 否 | — |
| `DSC07287.JPG` | 否 | — |

`-edited` 这种没有分隔符的不认，避免误伤本来就叫这个名字的原始文件。

同一张照片同时存在 `-ed` 和 `-ed2` 时，原图只归档一次，不会重复计数。

## 六、命令速查

```
photoflow gui                           打开图形界面（双击 photoflow.bat 也行）
photoflow new <批次>                     建 04/05/03/99 四个目录
photoflow ingest <源目录> <批次>          按扩展名分发 RAW/JPG
photoflow archive <批次>                 已修照片的原图 05 -> 99
photoflow doctor                         全库体检（只读）

通用参数：
  --apply      确认清单后真正执行（不加只预演）
  --root PATH  指定照片库根目录（不传时读配置文件；都没有才落到内置默认值）
  --force      new 专用，放过日期格式不规范（安全校验不可绕过）
  --dedupe     ingest 专用，卡内同名不同内容时自动加 _2/_3
  --verify     ingest 专用，复制后逐个比 SHA-256（慢，能挡住静默损坏）
```

所有会改动文件的命令默认都是预演，先看清单再 `--apply`。

## 七、日志

归档日志：`99_图库\原图JPG归档\_logs\archive-YYYY-MM.tsv`

每行一条：时间、批次、文件名、源路径、目标路径。`99` 不被极相册索引，放这里不会污染时间线。
