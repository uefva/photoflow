# photoflow — Lightroom + NAS 摄影工作流工具

一个把「相机出片 → 修图 → 归档」这条链路上所有机械劳动自动化的小工具。

目标只有一个：**每张照片在 NAS 相册的时间线里只出现一次**——修过的看成品，没修过的看原图，归档完的老照片自动退出时间线。不需要手动去重，也不需要记住哪张修过。

适用于 Windows + Lightroom Classic + 带相册功能的 NAS。

---

## 一、先说清楚：NAS 相册是怎么显示照片的

这套工作流的全部设计，都建立在一个前提上：**NAS 自带的相册，只显示你让它索引的目录。**

相册不是文件管理器。它做三件事：扫描被加入索引的目录、读取每张照片的拍摄时间、把所有照片按时间排成一条时间线。所以打开相册看到的是一片按日期铺开的照片流，完全看不出谁原本躺在哪个文件夹里。

关键在于索引是**目录级**的。你可以把某个目录整个排除在外，里面的照片就彻底不出现在时间线上——文件一张没少，只是不展示。

本文以极空间的相册为例。群晖 Synology Photos、威联通 QuMagie 的机制类似，只是入口名称不同。判断自己的 NAS 能不能用这套流程，标准只有一条：**能不能按目录排除索引**。能，下面的东西就成立；不能，得换思路。

两个实际约束：

- **RAW 不能索引。** 相册生成不了 RAW 的预览图，索引进去只会得到一堆坏图或占位图，把时间线搞乱。
- **不索引 ≠ 删除。** 被排除的目录照常可以用文件管理器打开、复制、备份，只是不参与时间线展示。

## 二、核心思路：用索引范围做去重

把照片库分成三层：

```
底片层   04_RAW原图/        相机 RAW，只进不改，不索引
工作层   05_JPG图/          待修的原图，索引
         03_缓存-调色ed/    修图成品，索引
归档层   99_图库/原图JPG归档/  已修照片的原图，不索引
```

去重不是靠数据库，而是靠**目录索引的取舍**：

一张照片修完后，成品落在**成品目录**（被相册索引），它的原图从**原图目录**（被索引）移动到**归档目录**（不索引）。于是相册里这张照片只剩成品一份。没修的照片原图还留在原图目录，相册显示原图。

整个过程不需要给照片打标记、建数据库或写 sidecar 文件，靠的只是「这个目录索引、那个目录不索引」。

## 三、目录结构

```
<照片库根目录>/
├── 03_缓存-调色ed/<批次>/      修图成品，文件名带 -ed
├── 04_RAW原图/<批次>/          RAW 底片
├── 05_JPG图/<批次>/            待处理原图
└── 99_图库/原图JPG归档/<批次>/  已归档原图
    └── _logs/                  归档日志
```

对应到 NAS 相册的索引设置：

| 目录 | 放什么 | 加入相册索引 |
|---|---|---|
| `03_缓存-调色ed` | 修图成品 | 是 |
| `04_RAW原图` | RAW 底片 | 否（相册无法预览） |
| `05_JPG图` | 待处理原图 | 是 |
| `99_图库/原图JPG归档` | 已归档原图 | 否（归档即退出时间线） |
| `99_图库/原图JPG归档/_logs` | 脚本日志 | 否 |

四个业务目录用同一套「批次名」，一一对应。批次名格式 `YYYY-MM-DD-地点`，例如 `2026-11-26-梧桐山`。

下文为了读着顺，统一用「RAW 目录 / 原图目录 / 成品目录 / 归档目录」指代这四处，不再写目录编号。

这四个文件夹的名字不是写死的：界面最右边的「设置」页签可以改，改完命令行也会跟着用新名字。配置存在 `%USERPROFILE%\.photoflow.json`，改坏了删掉就恢复默认。

## 四、使用流程

![工作流总览：建批次 → 从卡分发 → 选片修图 → 导出成品 → 归档原图](images/workflow.svg)

用图形界面时，顶部有一个「当前批次」，建批次、分发、归档三个页签都读这一个值，整场拍摄只需要填一次，不用在每个页签各选一遍。

### 1. 建批次

```bash
photoflow new 2026-11-26-梧桐山 --apply
```

一次建好 RAW、原图、成品、归档四个同名目录。省掉手打四遍目录名、打错一个就对不上的问题。

### 2. 从卡里分发

```bash
photoflow ingest F:\DCIM 2026-11-26-梧桐山 --apply
```

按扩展名自动分流：相机 RAW 进 RAW 目录，JPG / HEIC / PNG / TIFF 进原图目录，视频等其余文件跳过并提示。

### 3. 修图

Lightroom Classic 从 RAW 目录读底片。导出时用的预设里配两件事：

- 文件命名模板：`{Filename}-ed`
- 导出位置：直接指向 `03_缓存-调色ed/<批次>/`

这样「导到本地 → 拷进归档目录 → 逐个改名」三个动作合成一个，文件名自动带 `-ed`。

### 4. 归档

```bash
photoflow archive 2026-11-26-梧桐山 --apply
```

扫描成品目录里的 `-ed` 文件，剥掉后缀得到原名，去原图目录找同名原图，移进归档目录。这一步就是让照片在相册里「换一份」：成品进时间线，原图退出。

没修的原图原地不动，继续在相册里可见。

### 5. 体检

```bash
photoflow doctor
```

只读不写。检查批次命名、四个目录是否对齐、有没有散落文件、有没有空目录，以及最关键的——**有没有「已经修了但原图还没归档」的漏网之鱼**。漏归档意味着相册里同时出现成品和原图，这就是重复照片的唯一来源。

## 五、命令参考

```bash
photoflow gui                           打开图形界面（双击 photoflow.bat 也行）
photoflow new     <批次>                建 RAW / 原图 / 成品 / 归档四个目录
photoflow ingest  <源目录> <批次>        按扩展名分发 RAW / JPG
photoflow archive <批次>                已修照片的原图移进归档目录
photoflow doctor                        全库体检（只读）

通用参数
  --apply       确认清单后真正执行；不加只预演
  --root PATH   指定照片库根目录
  --force       new 专用：放过日期格式不规范
  --dedupe      ingest 专用：卡内同名不同内容时自动加 _2/_3
```

**所有会改动文件的命令默认都是预演。**先打印「将要做什么」的完整清单，确认无误再加 `--apply`。设计上宁可多敲一次命令，也不接受一次不可逆的误操作。

## 六、文件名约定

工具靠文件名判断「哪张成品对应哪张原图」。

| 成品文件名 | 匹配到的原图 |
|---|---|
| `DSC07287-ed.JPG` | `DSC07287.JPG` |
| `DSC07287-ed2.JPG` | `DSC07287.JPG` |
| `DSC07287-ed-2.JPG` | `DSC07287.JPG` |
| `DSC07287-ed-Edit.JPG` | `DSC07287.JPG` |
| `DSC07287-已增强-降噪-ed.JPG` | `DSC07287.JPG` |
| `DSC07287-Enhanced-NR-ed.JPG` | `DSC07287.JPG` |

Lightroom 的 AI 降噪会派生出 `原名-已增强-降噪.dng`（英文界面 `-Enhanced-NR`），从它导出的 JPG 会带上这个中缀。工具在匹配前会自动剥掉，不需要手动改名。

`DSC07287-edited.JPG` 这种没有分隔符的**不认**，避免误伤本来就叫这个名字的原始文件。

## 七、几个安全设计

这些细节不显眼，但决定了工具能不能放心用于不可重建的原始素材。

**重复判定看内容，不看大小。**同名文件先比大小，大小相同再比 SHA-256。两张不同照片恰好字节数相同的情况极少但存在，只看大小会造成静默丢片。

**永不覆盖。**目标已存在且内容不同，一律报冲突并停下，不覆盖、不猜测。归档时如果归档目录里已有同名但内容不同的文件，同样拒绝处理。

**匹配不唯一就不动手。**同一个主名在源目录里对应多个候选（多扩展名、多个子目录）时，只列出候选让人判断，不自动挑一个移动。

**批次名做路径校验。**拒绝含路径分隔符、Windows 保留字符、控制字符的名字，并确认最终路径没有跑出库目录。

**统计不注水。**归档结果分四类报账：真正归档几个、已在归档中几个、内容冲突几个、失败几个。跳过的不计入成功。

## 八、安装

需要 Python 3.7+，Windows 自带 `py` 启动器即可。

```
photoflow.py           主程序，单文件，无第三方依赖
photoflow.bat          命令行入口，转发给 py -3
test_photoflow.py      回归测试，18 个用例
```

把前两个文件放到任意目录，加入 PATH，或在同目录下执行。照片库路径通过 `--root` 传入，也可以改脚本顶部的 `DEFAULT_ROOT` 常量。

跑测试：

```bash
python test_photoflow.py
```

测试全部在临时目录里造数据，不碰真实照片。

## 九、已知限制

- 只处理「一张成品对应一张原图」的场景。同一张原图导出多个版本（`-ed` 和 `-ed2` 并存）时只归档一次，其余会提示，不会重复移动。
- 归档匹配基于文件名，不基于 EXIF 或图像内容。成品和原图的字节必然不同（一个是修过的），所以无法用哈希校验配对关系。
- 批次名格式校验是建议性的，`--force` 可以放过；但路径安全校验不可绕过。
- 依赖 NAS 相册能按目录排除索引。如果你的相册只能实时扫描全库、不能按目录关掉，这套流程的前提就不成立，需要改用别的去重方式。
